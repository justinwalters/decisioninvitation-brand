# Website and product surfaces

The public identity reference belongs at `decisioninvitation.com/brand`. This guide governs presentation, not deployment authority. A local page, archive, or successful build is not proof the public route is live.

## Public brand reference

Present, in this order: the product name and primary idea; the meaning of the identity; signature options and use; palette and accessibility; type; graphic language; messaging; usable downloads and version/status. Make the identity visible before explaining its files. A reader should understand the brand without needing GitHub.

`Catalyst of analysis.` is the leading idea. Follow it with a plain-language explanation: DecisionInvitation helps a decision owner frame a question, invite perspectives separately, and turn the analysis into a clear next move. `Ask separately. Decide clearly.` is supporting language, not a competing headline in the same visual tier.

This hierarchy is for the brand reference. Preserve the existing homepage lead, `Better input. Clearer decisions.`, and its warm supporting language. The user values those words; the core strategic idea does not require a replacement homepage hero. See [Messaging and voice](messaging-and-voice.md) for the exact foundation.

The public preview must disclose that the identity is proposed while that is true. Downloads must carry matching version and status. Show only public assets, public standards, and illustrative content; internal approval lists, participant examples, and operational receipts are not public brand material.

## Composition and hierarchy

- Use Paper as the main reading field, Ink as the anchor, and Mist for supporting structure. Use Ink sections sparingly for a distinctive moment. Orange is a small signal, not the page's operating color.
- Use a 12-column desktop editorial grid, a 4-column narrow grid, and content-based reading widths. Keep paragraphs near 60–75 characters. Avoid full-width prose.
- Make the headline the dominant element. No stock dashboard decoration, generic glowing objects, autonomous-AI imagery, or piles of interchangeable cards.
- Demonstrate a single question moving through perspectives to a possible next step. Mark all fictional product examples as illustrative; do not render mock controls as functional forms.
- Respect the supplied logo clear space. Keep navigation quiet and product-first; parent attribution is secondary footer material.

## Interface states

Primary action: Ink fill with White or Paper text. Secondary action: Ink text with a visible boundary on a light field. Orange is not a normal-sized button text/background pair with White. Links are distinguishable without color. Keyboard focus must remain visible on both light and dark fields; use a tested two-layer ring when a single color cannot contrast against both sides.

Every form has persistent labels, a concise explanation of the decision being made, and text errors tied to their fields. Distinguish saving from saved, invitation prepared from invitation delivered, and proposed summary from owner decision. Never show a success state before a real receipt. Data-bound views need loading, empty, denied, revoked, expired, unavailable, and long-content states. Do not add animation to imply unimplemented analysis.

Support 320 CSS pixel widths without horizontal page scrolling. Check 200% text zoom and reflow, keyboard order, font fallback, reduced motion, visible focus, color-independent state, and link targets. Headings remain semantic, and visual reading order follows document order. A fixed header must not hide anchors or focused content.

## Product versus marketing

Marketing can express possibility; product UI must describe the current state and the action's consequence. Keep promotional phrases out of critical consent and access copy. Sensitive pages must not load unnecessary third-party fonts, trackers, or decorative media. Brand work does not authorize new telemetry.

Metadata uses the plain product name, factual descriptions, the production domain only when verified, and the current social-preview image. Never add structured ratings, organization claims, certifications, or customer names without evidence. A canonical URL is an intended address, not a deployment receipt.

Before handoff, record the local build result separately from archive delivery, host acceptance, DNS/origin/SSL, root homepage acceptance, and `/brand` route acceptance. The product's existing homepage and invitation routes must remain intact.
